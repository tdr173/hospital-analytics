Use Case Name: Analyze Patient Cohorts with HospitAI

Primary Actor: Manager

Stakeholders and Interests:
1) Manager: wants to extract actionable clinical insights from the Synthea patient dataset with minimal effort, using clustering and sequential pattern mining.
2) Hospital Administration: wants clustering results and sequential patterns stored persistently for audit and reporting purposes.
3) Gemini LLM Service (Supporting Actor): expects well-structured prompts and returns natural-language cluster summaries.

Preconditions: Manager is authenticated and authorized on the HospitAI platform. The Synthea dataset CSV files are available at the configured path.

Postconditions: Patient data is loaded into PostgreSQL, clustering results with AI-generated summaries are persisted, and frequent sequential clinical patterns are available for the Manager to review.


1.1 Main Success Scenario (Basic Flow)
Use-Case Start: This use case starts when an authorized Manager initiates the full analytical pipeline on the HospitAI platform to extract insights from the Synthea patient dataset.

    1.  Manager triggers the ETL pipeline on the HospitAI platform.
    2.  System validates and loads patient data from the Synthea dataset into PostgreSQL.
    3.  Manager initiates the K-Prototypes clustering analysis.
    4.  System applies the K-Prototypes algorithm to cluster patients by clinical and demographic similarity.
    5.  System generates natural-language summaries for each discovered cluster via Gemini LLM.
    6.  System displays the clustering results and visualizations to the Manager.
    7.  Manager explores the clusters and requests the heatmap and PCA comparison plots.
    8.  Manager selects a cluster in the Frequent Sequences view.
    9.  System runs PrefixSpan and displays the closed sequential patterns ordered by descending support.
    10. Manager reviews the discovered patterns and their AI-generated clinical interpretations.

Use-Case End: The Manager has reviewed the K-Prototypes clustering results with AI-generated summaries and the frequent sequential clinical patterns for the selected patient cohort.


2.2 Extensions (Alternate Flows)

2a. Invalid or incomplete data detected:
    1. System identifies data quality violations or missing critical fields in the extracted records.
    2. System rejects the pipeline run and notifies the Manager via an error report.
    3. Use case ends.

4a. K-Prototypes algorithm fails to converge or produce valid clustering results:
    1. System detects a convergence error or runtime exception in the clustering algorithm.
    2. System displays an empty-state failure message to the Manager.
    3. Use case ends.

5a. Gemini LLM service is unreachable or returns an error response:
    1. System detects that the Gemini API is unavailable or returns an error response.
    2. System saves the clustering results without AI-generated summaries.
    3. System notifies the Manager that cluster summaries are temporarily unavailable.
    4. Flow resumes at Step 6 of the Basic Flow.

9a. No closed sequential patterns exceed the minimum support threshold:
    1. System detects that no patterns meet the configured support threshold.
    2. System displays an empty-state message in the Frequent Sequences view.
    3. Use case ends.
